## 2. Границы тестирования (Scope)

### Входит в проверку
- Авторизация: успешный вход, вход с неверным паролем, выход из учётной записи.
- Полный CRUD новостей (заполнение всех полей, редактирование, удаление с подтверждением и отменой).
- Фильтрация новостей: по дате (сегодня, неделя, месяц), по категории, комбинация фильтров.
- Просмотр цитат: отображение списка, разворачивание комментария через шеврон.
- Навигация между экранами, работа системной кнопки «Назад».
- UI-элементы: адаптация к повороту экрана, видимость элементов.
- Отрицательные сценарии: пустые поля при создании новости, удаление последней новости, отсутствие интернета.
- Обработка ошибок: сообщения при недоступности сети, валидация полей ввода.

### Не входит в проверку
- Регистрация новых пользователей (функция отсутствует).
- Серверная часть (API, база данных, производительность бэкенда).
- Стресс-тестирование и нагрузочное тестирование.
- Безопасность на уровне передачи данных.
- Совместимость со всеми версиями Android – тестируется выборочно на Android 10 (эмулятор).

## 3. Типы тестирования

| Тип тестирования | Ручное | Автоматизированное | Обоснование |
|------------------|--------|--------------------|--------------|
| Функциональное | ✅ | ✅ | Проверка соответствия заявленным функциям. Ключевые сценарии (логин, создание новости) автоматизированы. |
| UI (графический интерфейс) | ✅ | ✅ | Проверка видимости, расположения, соответствия макету. Частичная автоматизация (проверка наличия элементов). |
| Навигационное | ✅ | ❌ | Проверка переходов и работы кнопки «Назад» – эффективнее выполняется вручную. |
| Юзабилити | ✅ | ❌ | Оценка удобства и интуитивности – не подлежит автоматизации. |
| Совместимость | ✅ | ❌ | Проверка на разных версиях Android и разрешениях экрана – ручная выборочная. |
| Отрицательные сценарии | ✅ | ✅ | Неверный пароль, пустые поля, отключение сети – частично автоматизированы. |
| Регрессионное | ❌ | ✅ | Автотесты покрывают критический функционал для быстрой проверки после изменений. |

## 6. Риски и что с ними делать

| Риск (что может пойти не так) | Вероятность | Насколько сильно помешает | Что сделаем, чтобы избежать или уменьшить проблему |
|-------------------------------|-------------|---------------------------|------------------------------------------------------|
| Нет чёткого описания, как должно работать приложение — только «покликай сам» | Высокая | Средне | Сами исследуем приложение, запишем все экраны и логику. Если непонятно — уточним у руководителя. |
| Эмулятор в Android Studio тормозит или не запускается | Средняя | Сильно | Запустим тесты на реальном телефоне (Samsung A50). |
| У элементов на экране нет стабильных `id`, они генерируются каждый раз | Высокая | Сильно | Будем искать кнопки и поля по тексту, по соседним элементам или по родительскому контейнеру. |
| После одного теста остаются созданные новости, и следующий тест падает | Средняя | Средне | После каждого теста будем удалять всё, что создали (отдельный метод очистки). |
| Критический баг в приложении не даёт пройти даже один тест (например, вылет при входе) | Низкая | Сильно | Сначала вручную проверим, что приложение вообще работает (smoke-тест), потом уже запускаем автотесты. |
| Несовместимость версий: библиотека Espresso или Allure не дружит с версией Android Studio или Gradle | Средняя | Сильно | В `build.gradle` укажем проверенные стабильные версии библиотек. Перед началом работ обновим Android Studio до актуальной стабильной версии. |
| Не хватит времени на отладку тестов из-за неожиданных проблем с UI | Средняя | Средне | Заложим в расписание дополнительные 8 часов «на риски». Будем писать простые тесты, сначала самые важные (логин, создание новости). |

## 7. Расписание работ (7 дней)

**Общая длительность:** 56 часов (7 дней по 8 часов)  
**Основные работы:** 48 часов  
**Резерв на риски:** 8 часов

| День | Часы | Задачи |
|------|------|--------|
| 1 | 8 ч | Ручное исследование приложения, составление чек-листа (`Check.xlsx`). |
| 2 | 8 ч | Детализация тест-кейсов (`Cases.xlsx`), минимум 20 кейсов. |
| 3 | 8 ч | Настройка проекта в Android Studio, добавление зависимостей, реализация Page Object для экрана авторизации. |
| 4 | 8 ч | Автоматизация сценариев: логин, выход, просмотр списка новостей, создание новости. |
| 5 | 8 ч | Автоматизация сценариев: фильтрация, удаление новости, отрицательные тесты (неверный пароль, пустые поля). |
| 6 | 8 ч | Подключение Allure, добавление аннотаций и скриншотов при падении, генерация отчёта. |
| 7 | 8 ч | Финальная проверка, упаковка отчёта в ZIP, отправка ссылки на репозиторий руководителю. |

**Использование резерва (8 часов):**
Если возникают проблемы (эмулятор не запускается, библиотеки несовместимы, тесты падают по непонятным причинам) — берём время из резерва, сдвигая менее приоритетные задачи (например, часть отрицательных тестов или украшательство отчётов). Если резерв не понадобился — используем его для дополнительной отладки или расширения покрытия.
